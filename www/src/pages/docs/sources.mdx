# Sources

A source is the host Gitea Mirror pulls repositories from. Each account can connect several sources at once, managed as a list in the first card on the Connections tab of the Configuration page.

| Source | Covers | Default instance |
| --- | --- | --- |
| GitHub | github.com and GitHub Enterprise | `https://github.com` |
| GitLab (beta) | gitlab.com and self-hosted GitLab | `https://gitlab.com` |
| Gitea / Forgejo (beta) | Codeberg and any self-hosted Gitea or Forgejo | `https://codeberg.org` |
| Git URL (beta) | Any host that can be cloned over http(s): cgit, gitweb, Gitflic, kernel.org and the like | none, the host is required |

GitHub to Gitea is the supported path. GitLab, Gitea / Forgejo and Git URL carry a BETA pill in the dropdown: they are tested end to end against real hosts, but have had less time in the field. Sources other than GitHub also carry a short note under the dropdown saying what they cannot mirror.

## Choosing a source

Click **Add source** on the Sources card and pick the host. The editor adapts to it:

- **Instance URL** is empty for github.com, gitlab.com or codeberg.org. For your own instance enter its base URL, for example `https://github.example.com`, `https://gitlab.example.com` or `http://gitea.local:3000/gitea`. Values without a scheme get `https://` added.
- **Username** and **Personal access token** hold the account and token on the selected host.
- The **Test** button makes a live authenticated call against the selected host, so you can confirm the token before saving.

For GitHub Enterprise Server, enter the server's address as the Instance URL; the API is read from its `/api/v3` path. GitHub Enterprise Cloud with data residency serves its API at `https://api.TENANT.ghe.com`, which that field cannot express, so set the `GH_API_URL` environment variable for it. See [Environment variables](/docs/environment-variables/#source). `GH_API_URL` applies to every source that points at github.com, so connect an Enterprise Server as its own source with its Instance URL instead.

## Git URL sources

A Git URL source is for hosts that have no API Gitea Mirror knows, only repositories that can be cloned. It stands for one host:

- **Host URL** is required, for example `https://git.example.org`. Only the host is kept; a path pasted with it is dropped, because each repository brings its own.
- **Username** and **Password or token** are only needed when the host asks for a login to clone. They are sent as HTTP basic auth and handed to the destination for its own fetches. With only a password or token, the username `git` is used.
- **Test** checks that the host answers. Repositories are checked one by one when you add them.

Repositories are added one at a time with **Add by URL** on the Repositories page: paste the clone URL, such as `https://git.example.org/team/project.git`. The host must match a connected source. Gitea Mirror asks the host for its refs the way `git ls-remote` does, tries the URL with and without `.git`, and stores the one that answered. A repository that needed the login is recorded as private.

What to expect:

- Branches and tags are mirrored. There are no releases, issues, pull requests or wikis to read.
- There is nothing to list, so there is no import, no auto import, no organizations and no starred repositories.
- Cleanup never treats these repositories as deleted upstream.
- Force push detection is not available. For protection against rewritten history, use the **Always Backup** snapshot strategy; see [Force-push protection](/docs/force-push-protection/).
- Only http and https URLs work. SSH remotes are not supported.
- The folder a repository sits in is used as its owner, so `https://git.example.org/team/project.git` is owned by `team`. A repository at the root of the host is owned by the host name.

## Tokens

The card lists the scopes it needs and links to the token page of the selected instance.

| Source | Where to create the token | Scopes |
| --- | --- | --- |
| GitHub | Settings, Developer settings, Personal access tokens (classic) | `repo`, `read:org` |
| GitLab | Preferences, Access tokens | `read_api`, `read_repository` |
| Gitea / Forgejo | Settings, Applications | `read:repository`, `read:user`, `read:organization` |

The card asks for `admin:org` on GitHub; `read:org`, one of its checkboxes, is all the app uses. [Tokens and permissions](/docs/tokens/) explains each scope.

Without a token, GitLab and Gitea / Forgejo only show the configured user's public repositories and starred repositories. Adding a public repository by URL works without a token on every source.

Tokens are encrypted with AES-256-GCM before they are stored, whether they come from the form or from the environment.

## What each source can mirror

The code itself is copied by the destination: Gitea and Forgejo pull from the source as a plain git remote, and the push engine used for GitHub and GitLab destinations clones and pushes the same way. Sources therefore differ only in what their API offers on top of git.

| | GitHub | GitLab | Gitea / Forgejo | Git URL |
| --- | :---: | :---: | :---: | :---: |
| Code, branches, tags | yes | yes | yes | yes |
| Wiki | yes | yes | yes | no |
| LFS objects | yes | yes | yes | untested |
| Scheduled sync | yes | yes | yes | yes |
| Auto import of new repositories | yes | yes | yes | no |
| Cleanup of repositories deleted upstream | yes | yes | yes | no |
| Entire organizations (GitLab: top level groups) | yes | yes | yes | no |
| Starred repositories | yes | yes | yes | no |
| Private repositories | yes | yes | yes | yes, with a login |
| Add a single repository by URL | yes | yes | yes | yes |
| Issues, pull requests, labels, milestones, security advisories | yes | no | no | no |
| Releases with assets | yes | no | yes | no |
| Star lists | yes | no | no | no |
| Force push detection | yes | no | no | no |

The GitHub only rows read the GitHub API. With another source the corresponding switches in the mirror settings are disabled and say why. Releases are the exception: Gitea and Forgejo expose them through their own API, so a Gitea, Forgejo or Codeberg source mirrors releases and their assets with that instance's token, or anonymously for a public repository. A Forgejo release asset can also be a link to any address. Those are downloaded without your token, only from public addresses, and only up to 512 MB and 15 minutes; anything else is skipped with a warning in the log. Wiki and LFS also depend on the destination: they travel to Gitea and Forgejo, not to GitHub or GitLab. See [Destinations](/docs/destinations/).

## Adding repositories

Repositories reach the database in two ways.

**Import** discovers what the token can see on the source: the account's own repositories, the organizations or groups it belongs to, and its starred repositories, filtered by the selection options on the card (private, public, archived, forks, collaborator repositories, starred). Scheduled syncing can repeat the discovery so new repositories are picked up on their own.

**Add by URL** takes a single repository from the Repositories page. The dialog accepts what you are likely to have on the clipboard: a browser URL, a clone URL, an SSH remote, the `owner/repo` shorthand, or a deep link into the repository such as a file or an issue. Nested GitLab groups are fine, so `https://gitlab.com/group/subgroup/project` resolves to the project in the subgroup. The Organizations page accepts a profile URL or a bare name the same way. The server picks the connected source with the URL's host and resolves the reference there; a URL for a host with no connected source is refused.

## Behaviour to know about

**The source locks once repositories are imported.** The dropdown and the Instance URL then show a lock note with the number of repositories imported from that host, and a **Change** button. Changing the source is still possible, but only after a confirmation that spells out what happens:

- Repositories already imported stay tied to the current source and keep syncing.
- Cleanup ignores them, and mirroring one of them again is refused until it is removed and added from the new source.
- New imports come from the new source only.

A save that tries to switch a locked source without that confirmation is refused by the API, and a `SOURCE_PROVIDER` or `SOURCE_URL` value that disagrees with a locked source is ignored on boot with a warning in the log.

**Removing a source that has imported repositories asks for confirmation.** Those mirrors keep syncing on the destination with the credentials they were created with, but cleanup leaves them alone.

**Public only sources.** Adding a public organization without an account, see [Repositories and organizations](/docs/repositories-and-organizations/), creates a source with no token, shown as **Public only** on the Sources card. It imports the public repositories of the organizations you add, but finds no personal or starred repositories. Its API calls are anonymous, so on GitHub they share the limit of 60 requests an hour per IP address, and a large organization can end up with partial metadata; the mirrors themselves are plain git clones and use no API requests. Add a username and token to the source to turn it into a normal one.

**Each repository remembers its host.** A row imported from one host is never mirrored with another host's token, so switching sources cannot send a token to the wrong server.

**GitLab groups are flattened.** A project under `group/subgroup/project` lands in the organization `group` with the preserve strategy and keeps its full path as the repository's full name. The organization allowlist matches the top level group.

**GitLab internal projects are treated as private** when the mirror is created, because anonymous users cannot see them on the source either.

**Repository names come from the URL path**, not the display name. A GitLab project called "My Widget" with path `my-widget` mirrors as `my-widget`.

## Environment variables

| Variable | Default | Description |
| --- | --- | --- |
| `SOURCE_PROVIDER` | `github` | `github`, `gitlab`, `gitea` or `git`. `gitea` also covers Forgejo and Codeberg; `git` is a [Git URL source](#git-url-sources). |
| `SOURCE_URL` | per source | Base URL of the GitLab or Gitea / Forgejo instance. Ignored for GitHub. |
| `GITLAB_PAGE_SIZE` | `100` | Projects per GitLab listing request, from 10 to 100. Lower it for a slow GitLab that times out at 100; see [Environment variables](/docs/environment-variables/#source). |
| `GITHUB_USERNAME` | none | Username on the selected host. The name is kept for every source. |
| `GITHUB_TOKEN` | none | Token for the selected host, with the scopes listed above. |
| `GH_API_URL` | `https://api.github.com` | GitHub API base URL, for GitHub Enterprise. |

A self-hosted GitLab source declared through the environment:

```bash
SOURCE_PROVIDER=gitlab
SOURCE_URL=https://gitlab.example.com
GITHUB_USERNAME=your-gitlab-username
GITHUB_TOKEN=${GITLAB_TOKEN}
```

These variables set up the first source, and create it when there is none. Add more sources in the app. The [environment variables reference](/docs/environment-variables/) has the complete list, and the [configuration guide](/docs/configuration/) explains how seeded values relate to the form.

## Not yet

- Issues, pull requests, merge requests, labels, milestones and security advisories are read from GitHub only.
- Releases from GitLab are not mirrored. Gitea, Forgejo and Codeberg sources do mirror releases.
- The import filters on the card apply to all sources at once, and when one GitHub source hits its rate limit, the other GitHub sources of the same user pause with it.
